# Agent swarms work when ownership survives

**Useful swarms separate adaptive task selection from enforceable execution control.** People make them work through bounded specialist calls, hierarchical planners, test-driven work queues, and durable workflows—not simply by letting more agents converse. For Starfleet, the strongest candidate is an accountable orchestrator delegating narrow, verifiable tasks while ordinary software owns budgets, lifecycle, permissions, and approval gates. Research and coding experiments demonstrate substantial capability, but controlled evidence does not establish general coding superiority. Parallelism helps when work is independently diagnosable; it fails when workers converge on shared blockers or verification becomes ceremonial. This briefing, as of **November 9, 2026**, distinguishes documented semantics, reported outcomes, and recommendations; it does not authorize implementation.

## Who owns continuation determines the architecture

**Autonomous delegation means the model decides what work to assign or which worker to invoke.** A predetermined pipeline calling several models is multi-agent execution, but not necessarily autonomous delegation. Static topology and dynamic decisions coexist: code can register specialists and constrain transitions while a model chooses among them. Dynamic fan-out can instantiate many calls to an existing worker without generating new roles, processes, or permissions ([OpenAI orchestration](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md); [LangGraph workflows](https://docs.langchain.com/oss/python/langgraph/workflows-agents)).

In **manager/agents-as-tools**, the parent retains responsibility, calls a bounded specialist, receives a result, then continues. In **handoff routing**, the active conversation owner changes; the destination generally continues the interaction rather than returning through an intrinsic child-task join. OpenAI documents both, with conversation history passed to handoffs by default unless filtered. A customer-support transfer and a research assistant returning evidence are therefore different control contracts, despite both appearing as delegation ([manager versus handoff](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md); [handoff context](https://github.com/openai/openai-agents-python/blob/main/docs/handoffs.md)).

A **supervisor** repeatedly chooses the next worker and interprets progress. Microsoft’s Magentic implementation adds task/progress ledgers and stall-triggered replanning. **Hierarchy** composes supervisors or bounded managers, introducing ownership boundaries but also lossy context transfers. A **workflow graph** instead gives code/runtime responsibility for allowed transitions, dependencies, fan-out and joins; a model can still generate its work list. **Event-driven actors** exchange addressed messages or topic events, leaving correlation and joins to the application. Historical AutoGen Core illustrates the distinction: direct messages await handler results, whereas publication supplies no implicit response or join. A shared-state “blackboard” is another communication mechanism, not by itself an autonomous scheduler ([Magentic source](https://github.com/microsoft/agent-framework/blob/main/python/packages/orchestrations/agent_framework_orchestrations/_magentic.py); [LangGraph graph semantics](https://docs.langchain.com/oss/python/langgraph/graph-api); [AutoGen messaging](https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/framework/message-and-communication.html)).

These mechanisms suggest different uses: manager calls for scoped investigations and reviews; supervisors for evolving backlogs; graphs for gated, restartable work; handoffs for specialist-owned conversations; actors for asynchronous external workers. None inherently guarantees isolated workspaces, durable delivery, or correct completion.

## Successful workflows create independence before adding workers

**Cursor’s February 5, 2026 experiment is the clearest autonomous-planner example.** Equal peers coordinating through shared tasks lacked end-to-end ownership. A continuous executor that planned, spawned, monitored, reviewed, merged and judged became overloaded, stopped delegating, and prematurely finished. The reported final design separated a noncoding root planner, recursive subplanners, and narrow workers in individual repository copies. Workers returned results, concerns, deviations and discoveries to their requesting planner; completion woke planning again. This is event-driven replanning, not a fixed plan followed by a global barrier. However, Cursor deliberately tolerated broken intermediate commits and removed a bottlenecked integrator: its throughput is not evidence of production-ready accepted-code throughput ([primary account](https://cursor.com/blog/self-driving-codebases)).

**Anthropic’s February 5, 2026 compiler experiment used no orchestrator.** Sixteen Opus 4.6 workers selected tasks, claimed them through Git-tracked files, and exchanged work through a shared upstream from separate containers/clones. Nearly 2,000 sessions over two weeks consumed approximately two billion input and 140 million output tokens, costing just under $20,000, to produce a roughly 100,000-line Rust C compiler. Reported Linux 6.9 builds were substantial, but the demo retained external tooling, a GCC-dependent boot stage, inefficiencies and correctness limitations. Crucially, all workers initially converged on the same Linux blocker; a human-created GCC oracle restored partitionable debugging. The lesson is evaluator design, not proof that sixteen agents outperform one at equal cost ([experiment](https://www.anthropic.com/research/building-c-compiler)).

**Gas Town makes work durable beyond individual sessions.** Its documented workflow separates coordinator, task ledger, assigned worker, supervision and integration queue. Operational outcomes vary markedly: Tim Sehn’s January 15, 2026 trial produced four rejected PRs and an unexpected merge despite failed integration tests; his March 24 report described DoltLite passing 87,000 SQLite acceptance tests for approximately $3,000, with parallelism more useful early than near completion. These are distinct versions and supervised project accounts, not a stable failure rate or controlled speedup ([lifecycle design](https://github.com/gastownhall/gastown/blob/main/docs/design/polecat-lifecycle-patrol.md); [January trial](https://www.dolthub.com/blog/2026-01-15-a-day-in-gas-town/); [March trial](https://www.dolthub.com/blog/2026-03-24-a-week-in-gas-town/)).

Neil Macneale’s April 16 DumboDB account adds a stronger verification boundary: implementation and parity tests lived in separate repositories with distinct write tokens, while a coordinator could read both. The prototype reached 1,422 implemented parity tests, with 47 expected failures remaining. Yet exhausted workers sometimes left the coordinator waiting until a human intervened. **Independent test ownership and runtime liveness are separate requirements** ([field report](https://www.dolthub.com/blog/2026-04-16-two-weeks-in-gastown/)).

## Frameworks supply different contracts, not comparable reliability scores

The comparison below summarizes documented capabilities, not a performance ranking. Sources are living documentation/main branches; exact release availability must be pinned before adoption. Earlier notes consulted Context7 and primary sources; this synthesis rechecked the strongest status claims directly.

| Representative system | Delegation/control semantics | Recovery boundary and principal caveat |
| --- | --- | --- |
| **OpenAI Agents SDK** | Model-selected specialists as tools preserve manager ownership; handoffs transfer it. Code orchestration also supported. | Resumable run state and durable-execution integrations are documented; a nested call alone is not a durable job ([orchestration](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md); [running](https://github.com/openai/openai-agents-python/blob/main/docs/running_agents.md)). |
| **LangGraph** | Explicit graph/state; model-generated plans can drive dynamic worker fan-out and reducer-based joins. | Checkpoints and pending writes support recovery; persistence mode and replay-safe side effects matter ([durability](https://docs.langchain.com/oss/python/langgraph/durable-execution); [checkpoints](https://docs.langchain.com/oss/python/langgraph/checkpointers)). |
| **Microsoft Agent Framework** | Typed workflows plus group-chat, handoff and Magentic supervision; model and code control are distinct. | Durable extension exists separately; Python/.NET and hosting modes require separate verification ([overview](https://learn.microsoft.com/en-us/agent-framework/overview/); [durable extension](https://github.com/microsoft/agent-framework-durable-extension)). |
| **CrewAI** | Hierarchical manager delegates/reviews within configured crews; Flows supply event/state routing. | Full checkpoints now exist, but automatic writes are best-effort and callback restoration is constrained; hierarchy is not unrestricted parallel scheduling ([hierarchy](https://docs.crewai.com/en/learn/hierarchical-process); [checkpointing](https://docs.crewai.com/en/concepts/checkpointing)). |
| **Google ADK** | Code-defined sequential/parallel/loop agents coexist with model transfers and bounded agent tools. | Resumption needs persistent session/call correlation; resumed tools can execute more than once ([resumability](https://github.com/google/adk-python/blob/main/docs/guides/apps/resumability/index.md); [agent tools](https://github.com/google/adk-python/blob/main/docs/guides/tools/agent_tool/index.md)). |
| **Claude Code / OpenCode harnesses** | Native specialist delegation; Claude teams add shared tasks and peer messaging. | Claude teams remain experimental with resume/shutdown limitations; OpenCode documentation differs across versions. Neither separate context nor delegation alone proves filesystem isolation ([teams](https://code.claude.com/docs/en/agent-teams); [OpenCode agents](https://opencode.ai/docs/agents/)). |

**Status confidence is high for explicit notices, not for inferred maturity.** OpenAI Swarm’s README says it is experimental/educational and replaced by the Agents SDK. AutoGen’s prominent README notice says archived, unmaintained, and without Microsoft security fixes, directing users to Microsoft Agent Framework; lower maintenance-mode wording conflicts with that notice. Archive dates were not established. Microsoft’s “production-ready” successor language is a vendor assertion, not measured recovery evidence. No latest package version is claimed here ([Swarm notice](https://github.com/openai/swarm); [AutoGen notice](https://github.com/microsoft/autogen)).

## Controlled evidence argues against default coding swarms

Anthropic’s **June 13, 2025** production research report claimed an Opus 4 manager with Sonnet 4 workers outperformed a single Opus 4 agent by **90.2% on an internal research evaluation**. Absolute scores, sample and matched-cost ablation were not disclosed. This is neither a percentage-point gain nor a coding result. Its consumption comparison was approximately 4× chat tokens for agents and 15× chat tokens for multi-agent systems—**not 15× a single autonomous agent**. The architectural benefit was broad independent exploration and context compression; tightly coupled coding was explicitly a weaker fit ([original report](https://www.anthropic.com/research/multi-agent-research-system)).

The retrieved **April 8, 2026 revision** of *Towards a Science of Scaling Agent Systems* evaluated **260 configurations across six benchmarks and five architectures**, standardizing prompts, tools and compute. Centralized coordination improved financial reasoning by approximately 80.8% relative, while every tested multi-agent architecture degraded sequential PlanCraft performance by approximately 39–70%. SWE-bench Verified results degraded approximately 2–15%; Terminal-Bench was mixed. Coding configurations used only **20-instance subsets**, limiting precision and generalization. These findings concern the tested models, budgets and environments, not a universal prohibition on coding delegation. The January 28 Google summary described an earlier 180-configuration/four-benchmark version and should not be combined with the revision’s coding results ([revised paper](https://arxiv.org/html/2512.08296); [earlier summary](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)).

MAST’s retrieved **October 26, 2025 v3** analyzed 1,642 traces across seven frameworks, deriving fourteen failure modes from close analysis of 150 traces. Much of the larger corpus was model-annotated. Its evidence supports concrete risks—repetition, context loss, withheld information, premature termination, incomplete and incorrect verification—but not a fair framework leaderboard: tasks, models and sample sizes differed. **Reviewer agreement is not independent correctness evidence**, especially when reviewers share models, tests and the author’s framing ([paper and methods](https://arxiv.org/html/2503.13657)).

Confidence is therefore strongest in the documented control distinctions and observed failure mechanisms; moderate in the task-structure explanation for selective parallelism; low in any portable optimal team size, recursive depth, dollar savings or unattended success rate for Starfleet.

## Starfleet should evaluate bounded autonomy under durable control

**Recommendation, not established Starfleet architecture:** compare a bounded manager against a durable graph with model-proposed fan-out. The manager is simpler and preserves clear ownership; the graph adds explicit gates, joins and recovery but increases state/replay complexity. Add hierarchical supervisors only when subdomains justify extra planning and context boundaries. Choose an event-driven worker fabric when asynchronous placement or external jobs require it, accepting the additional delivery, correlation and orphan-management burden. Keep conversational handoffs separate from child-task scheduling.

The candidate execution contract should bind task/parent identity, objective, base revision, dependencies, permitted resources, deadline, budget, output artifact and acceptance evidence. A structured handoff should include changed artifacts, checks/results, deviations, unresolved risks and discoveries. Persist these outside model context; return compact evidence with provenance, not entire tool logs. Completion/failure events should wake the owning planner, while deterministic supervision detects missing heartbeats, expired claims and abandoned workers. This synthesizes Cursor’s upward handoffs, Gas Town’s durable work and Anthropic’s externalized context rather than copying any system wholesale ([Cursor](https://cursor.com/blog/self-driving-codebases); [Gas Town](https://github.com/gastownhall/gastown); [Anthropic Research](https://www.anthropic.com/research/multi-agent-research-system)).

**Session finished, output valid, checks passed, accepted, and integrated must remain distinct states.** Separate cancellation, failure, blocked work and budget exhaustion. Ordinary software should enforce descendant-wide spend/concurrency limits, deadlines, bounded retries and cancellation propagation. Persist attempts and side-effect correlation; reconcile uncertain outcomes before retrying non-idempotent operations. LangGraph’s asynchronous checkpoint mode has a crash window; CrewAI can continue after automatic checkpoint failure; ADK warns of repeated tool execution on resume. Thus “supports persistence” is insufficient, and cancellation does not imply rollback ([LangGraph checkpoint modes](https://docs.langchain.com/oss/python/langgraph/checkpointers); [CrewAI limitations](https://docs.crewai.com/en/concepts/checkpointing); [ADK replay](https://github.com/google/adk-python/blob/main/docs/guides/apps/resumability/index.md)).

Concurrent writers should use separate worktrees/clones with controlled integration; task claims do not confer exclusive file ownership, and worktrees do not isolate credentials, ports or databases. Retain produced work until verified integration. Keep capabilities outside model control and treat retrieved content and peer messages as untrusted: the October 2024 *Prompt Infection* simulation demonstrated cross-role privilege composition, while Invariant’s May 26, 2025 GitHub MCP proof-of-concept induced private-data publication through malicious issue content. Neither establishes a production base rate, but both undermine the assumption that an agent boundary is an authorization boundary ([Prompt Infection](https://arxiv.org/html/2410.07283); [researcher disclosure](https://invariantlabs.ai/blog/mcp-github-vulnerability)).

**Open decisions requiring explicit user approval** remain: which task classes merit delegation; who can spawn children and whether recursion is allowed; context-sharing and workspace boundaries; integration/verification ownership; acceptable recovery and duplicate-side-effect risk; budget ceilings; and which actions require human approval. A framework’s model-approved “plan” must not substitute for user consent—Claude teams explicitly document approvals without asking the human. These are design questions, not an approved implementation sequence ([plan-approval semantics](https://code.claude.com/docs/en/agent-teams)).

## Conclusion

Starfleet’s differentiator should be **accountable delegation**, not maximal agent count. A planner can choose work adaptively without owning permissions, liveness or truth. The useful unit is a bounded task with durable ownership and independently checkable output; an additional agent is justified only when that unit improves delivery.

A proposed evaluation—not authorization—would compare a strong single agent, bounded manager and equivalent durable-graph team on representative tasks, separately holding total budget and wall-clock deadline constant. Measure verified acceptance, regressions, human review time, total cost, duplicate work and recovery under crashes, slow workers, canceled tasks and replayed side effects. That evidence should determine where autonomy expands; present research cannot choose Starfleet’s topology or operating limits in advance.
